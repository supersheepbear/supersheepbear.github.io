CS7638 机器人技术：SLAM 章节学习大纲

  1. 课程回顾与 SLAM 动机介绍 (Review and Motivation for SLAM)

    • 内容：回顾定位 (Localization)、追踪 (Tracking)、规划 (Planning) 和控制 (Control) 的核心概念，并引出在未知环境中同时进行定位和建图的必要性，即 SLAM 问题。

  2. 整合所有知识：构建一个虚拟机器人 (Putting It All Together: Building a Virtual Robot)

    • 内容：深入分析课程提供的 robot Python 类，理解其__init__、set、move 等关键函数的实现细节，特别是噪声模型如何影响机器人行为。

  3. 核心挑战：横向跟踪误差 (Crosstrack Error, CTE)

    • 内容：从几何和向量角度，详细拆解 CTE 的数学定义。理解为什么它是机器人路径跟踪控制中的核心指标。

  4. 动手实践：CTE 的代码实现 (Hands-on: Implementing CTE)

    • 内容：指导完成计算 CTE 的编程任务，重点讲解如何处理机器人超越当前路径线段的情况，并更新目标路径点。

  5. 参数的艺术：PD 控制器与路径平滑 (The Art of Parameters: PD Controller and Path Smoothing)

    • 内容：探讨 p_gain 和 d_gain (即 PD 控制器) 如何利用 CTE 来控制机器人转向。同时，讨论路径平滑参数 weight_smooth 的作用。

  6. SLAM 核心思想：什么是同时定位与建图？ (The Core Idea of SLAM)

    • 内容：正式引入 SLAM 的概念，解释为什么在没有预先提供地图的情况下，定位和建图是两个相互耦合、必须同时解决的“鸡生蛋，蛋生鸡”问题。

  7. 图 SLAM (Graph SLAM) 概览

    • 内容：介绍一种主流且直观的 SLAM 方法——图 SLAM。将其比喻为用“橡皮筋”连接机器人位姿和环境路标，形成一个待优化的网络。

  8. 图 SLAM 的数学基石：约束与信息矩阵 (Math of Graph SLAM: Constraints and the Information Matrix)

    • 内容：讲解如何将机器人的运动 (Motion) 和对路标的观测 (Measurement) 转化为数学上的“约束”，并用信息矩阵 Ω (Omega) 和信息向量 ξ (Xi) 来表示这些约束。

  9. 动手实践 I：构建图 SLAM 的运动约束 (Hands-on I: Building Motion Constraints)

    • 内容：指导完成第一个图 SLAM 编程任务，学习如何根据机器人的连续运动，逐步填充和更新 Ω 矩阵和 ξ 向量。

  10. 动手实践 II：加入路标观测约束 (Hands-on II: Incorporating Landmark Observation Constraints)

    • 内容：在已有代码基础上进行扩展，学习如何将机器人对路标的观测数据也转化为约束，添加到 Ω 和 ξ 中。

  11. 求解图 SLAM：神奇的矩阵魔法 (Solving Graph SLAM: The Magic of Matrix Operations)

    • 内容：揭示图 SLAM 的最终求解步骤：通过简单的矩阵求逆和乘法 (μ = Ω⁻¹ * ξ)，一次性计算出所有机器人位姿和路标位置的最优估计。

  12. 噪声与不确定性：真实世界的 SLAM (Noise and Uncertainty in the Real World)

    • 内容：分析当测量存在噪声时，图 SLAM 如何通过“松弛”那些“橡皮筋”（约束），找到一个全局最优的、最符合所有数据的解。

  13. 终极挑战：实现一个完整的 2D SLAM 系统 (The Ultimate Challenge: A Complete 2D SLAM System)

    • 内容：拆解并指导完成课程最后的综合性大作业，将之前所有学到的知识点融会贯通，处理包含多个路标和更长轨迹的复杂场景。

  14. 课程总结与未来展望 (Wrap-up and Future Outlook)

    • 内容：回顾 SLAM 的核心价值，总结图 SLAM 的优势与局限，并简要介绍其他 SLAM 方法和该领域的前沿发展。

第一章：课程回顾与 SLAM 动机介绍 (Review and Motivation for SLAM)

你好！欢迎来到 CS7638 课程的第六单元。在这一章，我们的核心目标是将之前所有零散的知识点——那些关于定位、追踪、规划和控制的理论与实践——像拼图一样组合起来，最终构建一个真正能够自主导航的智能机器人。而要实现这个宏伟目标，我们就必须面对并解决一个机器人领域皇冠上的明珠级问题：SLAM。

在正式揭开 SLAM 的神秘面纱之前，让我们先花点时间，稳固一下地基。

1.1 知识回顾：我们已经掌握的武器

想象一下，我们已经拥有一个工具箱，里面装满了各种强大的工具。这次课程的目标，就是教会你如何组合使用这些工具来完成一项复杂的工程。

  • 定位 (Localization): 核心任务是回答“我在哪里？”。前提是，我们已经有了一张精确的地图。课程中提到了斯坦福大学的自动驾驶车 Junior，它就是利用激光雷达扫描当前环境，然后与一张预先制作好的高精度地图进行匹配，通过粒子滤波器 (Particle Filters) 来实现厘米级的精确定位。
  • 追踪 (Tracking): 紧随定位之后，追踪要解决的是“我如何持续知道我的位置？”。它关注的是如何根据连续的运动和观测，平滑、准确地估计出机器人（或任何目标）的状态轨迹。
  • 规划 (Planning): 当我们知道了“我在哪儿”以及“要去哪儿”之后，规划就负责回答“我该怎么走？”。我们学习了像 A* 算法和动态规划 (Dynamic Programming, DP) 这样的路径搜索方法，它们能在给定的地图上找到一条从起点到终点的最优路径。
  • 控制 (Control): 这是执行的环节，回答“如何精确地按照规划的路径行驶？”。PID 控制器 (PID Control) 就是我们学到的核心工具，它通过不断地调整，让机器人的实际轨迹与期望轨迹之间的误差最小化。

这些概念的背后，是更底层的数学和算法工具：

  • 概率论 (Probabilities): 机器人世界充满不确定性，概率为我们提供了一个量化和推理不确定性的强大框架。
  • 滤波器 (Filters): 无论是卡尔曼滤波器 (Kalman Filters)、直方图滤波器 (Histogram Filters) 还是粒子滤波器 (Particle Filters)，它们都是在充满噪声的测量数据中估计出系统真实状态的核心算法。

1.2 💡 核心矛盾：“鸡生蛋还是蛋生鸡”的问题

回顾完我们已有的知识，一个关键问题浮出水面：

⚠️ 所有这一切——定位、规划、控制——几乎都依赖于一个重要的前提：一张预先存在的、准确的地图！

但是，如果机器人被投放到一个全新的、完全未知的环境中呢？比如：

  • 一个刚刚发生地震的救援现场。
  • 人类从未踏足过的火星表面。
  • 一个你刚刚搬进去的新家。

在这些场景下，我们没有地图。机器人无法进行定位，进而也无法进行有效的路径规划。这就引出了机器人学中一个经典的两难问题：

  • 要想精确地定位 (Localize)，你需要一张地图 (Map)。
  • 要想可靠地建图 (Map)，你需要精确的定位 (Localization)。

这就是著名的“鸡生蛋，蛋生鸡”问题。你不能凭空定位，也不能在不知道自己位置的情况下绘制地图。

✅ SLAM (Simultaneous Localization and Mapping)，中文译为“同时定位与地图构建”，正是为了解决这个核心矛盾而生的。它的任务就是让机器人在一个完全未知的环境中，从零开始，一边探索，一边绘制环境的地图，同时利用正在构建的这张地图来实时确定自己在其中的位置。

1.3 考点聚焦：温故而知新 (Quiz Time!)

课程通过几个小测验来检验我们对基础知识的掌握程度，这些也是考试中非常容易出现的对比分析题。让我们来深入剖析一下。

考点 1: 滤波器的比较

这是一个非常经典的对比表格，你需要牢牢记住它们各自的特点：

特性 / 滤波器 (Filter) 卡尔曼滤波器 (Kalman Filter) 直方图滤波器 (Histogram Filter) 粒子滤波器 (Particle Filter)
分布形态 (Distribution Type) 单峰 (Unimodal) ✅ 多峰 (Multimodal) ✅ 多峰 (Multimodal)
计算复杂度 (Complexity) 在状态空间维度上是多项式级 ⚠️ 维度灾难 (Exponential) ⚠️ 维度灾难 (Exponential)
机器人领域应用性 (Usefulness) ✅ 非常有用 ✅ 非常有用 ✅ 非常有用

深度解析:

  • 单峰 vs. 多峰 (Unimodal vs. Multimodal):
    • 卡尔曼滤波器基于高斯分布，而高斯分布只有一个峰值。这意味着它只能表示一个关于机器人位置的“最佳猜测”。如果机器人完全不知道自己在哪（比如，在一个对称的走廊里，它可能在左端，也可能在右端），卡尔曼滤波器会强制将这两种可能性平均，得出一个毫无意义的中间位置。
    • 直方图和粒子滤波器则可以在概率分布中表示多个峰值。它们可以同时表达“机器人有 70% 的可能在 A 点，有 30% 的可能在 B 点”，这对于解决全局定位和机器人被绑架问题 (Kidnapped Robot Problem) 至关重要。
  • 计算复杂度 (Computational Complexity):
    • 卡尔曼滤波器的计算量与状态维度的平方或立方成正比，相对高效。
    • 直方图滤波器将世界划分为网格，如果世界是三维的，网格数量会随分辨率呈指数级增长，这就是“维度灾难”。粒子滤波器虽然更灵活，但在高维空间中，为了有效覆盖状态空间，所需的粒子数量也可能指数级增长。

模拟考题 📝

问题: 一个机器人在一个大型对称的办公楼中启动，它没有任何关于其初始位置的信息。为了解决这个初始的“全局定位”问题，你认为使用卡尔マン滤波器还是粒子滤波器更合适？请解释你的理由，并说明所选滤波器在表示不确定性方面的关键优势。

参考答案: 应该选择粒子滤波器。因为在全局定位问题中，机器人最初可能位于多个不同的地方，其位置的概率分布是多峰 (multimodal) 的。粒子滤波器通过维护一个粒子集合来近似概率分布，能够有效地表示多个离散的可能性（每个粒子代表一个位置假设）。相比之下，卡尔曼滤波器基于单一的高斯分布，是单峰 (unimodal) 的，它无法表示多个分离的假设，会错误地将所有可能性平均到一个可能毫无意义的中间点。因此，粒子滤波器的多峰表示能力是其在此场景下的关键优势。

考点 2: 规划算法的比较
特性 / 规划器 (Planner) 广度优先 (Breadth-First) A* 动态规划 (DP) 平滑器 (Smoother)
作用于连续空间 (Continuous Space) 否 否 否 ✅ 是

通用规划 (Universal Plan) 否 否 ✅ 是 否
局部操作 (Local Operation) 否 否 否 ✅ 是

深度解析:

  • 连续 vs. 离散: A* 等算法通常在离散的图或网格上搜索。而 Smoother（路径平滑）则是在已经有了一条粗略路径（比如 A* 的输出）后，在连续空间中对这条路径进行微调，使其更适合机器人的物理运动。
  • 最优解: A* 在其搜索空间内能保证找到最短路径。DP 也能找到最优策略。而路径平滑只是对现有路径进行局部优化，不能保证全局最优。
  • 通用规划: A* 找到的是从一个特定起点到一个特定终点的路径。而动态规划可以计算出一个策略 (Policy)，告诉你从地图上任何一个点出发，下一步应该怎么走才能最优地到达终点。这是一个更“通用”的解决方案。

2.1 深入代码：robot 类的解剖

课程为我们提供了一个名为 robot 的 Python 类。这个类就是我们在这个虚拟世界中的化身。它封装了机器人的所有状态、能力和不确定性。让我们逐一解剖它的关键“器官”（方法/函数）。

🤖 __init__(self, length = 0.5) - 机器人的诞生

这是类的构造函数 (constructor)，当我们创建一个新的机器人实例时（例如 my_robot = robot()），这个函数就会被调用。

  • self.x = 0.0, self.y = 0.0, self.orientation = 0.0: 这定义了机器人的初始位姿 (Pose)。默认情况下，它诞生在世界的原点 (0, 0)，并且朝向正 x 轴方向（0 弧度）。
  • self.length = length: 定义了机器人的物理尺寸，这在更高级的运动模型（如自行车模型）中至关重要。
  • self.steering_noise, self.distance_noise, self.measurement_noise: 💡 这是本章最重要的概念之一！ 这三个变量代表了机器人世界中的不确定性 (Uncertainty) 或 噪声 (Noise)。
    • steering_noise: 控制噪声。模拟了方向盘或舵机的误差。即使你命令机器人转 10 度，它实际转动的角度可能是在 10 度附近的一个高斯分布中随机采样。
    • distance_noise: 里程计噪声。模拟了轮子打滑等情况。即使你命令机器人前进 1 米，它实际移动的距离也是在 1 米附近的一个随机值。
    • measurement_noise: 传感器噪声。模拟了 GPS 或其他定位传感器的误差。即使机器人真实位置在 (10, 20)，它的传感器读数也可能是在这个真实位置附近的一个随机点。
🔩 set(self, new_x, new_y, new_orientation) - “上帝之手”

这个函数允许我们完美地、无误差地将机器人放置在任意一个指定的位姿。你可以把它想象成一个“传送”功能。在初始化或者测试特定场景时非常有用。

  • self.orientation = float(new_orientation) % (2.0 * pi): 注意这里的取模运算 (%)。它确保了机器人的朝向始终被限制在 [0, 2π) 的范围内，这是一个非常标准的处理角度的做法。
⚙️ move(self, grid, steering, distance, ...) - 核心运动模型

这是机器人移动的执行函数，也是最复杂、最关键的部分。它模拟了机器人从一个位姿到下一个位姿的状态转移 (State Transition)。

  1. 施加噪声: 函数的第一步不是直接使用传入的 steering 和 distance，而是给它们加上前面定义的高斯噪声。

    python

    ✅ 这深刻地体现了理论与现实的差距：机器人执行的永远是带有噪声的命令。

  2. 运动学模型 (Kinematic Model): 接下来，代码根据转向角度的大小，选择了两种不同的模型来计算新的位姿：

    • 直线近似 (Straight Line Motion): 如果转向角非常小 (abs(turn) < tolerance)，就认为机器人在做直线运动。这是一种计算上的简化。
    • 自行车模型 (Bicycle Model): 当转向角较大时，使用一个更真实的自行车模型。它计算出一个转弯半径 radius，并认为机器人是沿着一个圆弧运动。新的位置是根据这个圆弧的几何关系计算出来的。

  3. 返回新状态: move 函数会创建一个全新的 robot 对象并返回。原有的机器人对象保持不变。这是一种被称为“不可变性 (immutability)”的良好编程习惯。

🛰️ sense(self) - 机器人的“眼睛” (GPS)

这个函数模拟了机器人的定位传感器。它返回机器人的 (x, y) 坐标，但同样地，这个返回值被叠加了高斯噪声 self.measurement_noise。所以，机器人永远无法完美地知道自己的确切位置。

📊 measurement_prob(self, measurement) - 概率计算

这个函数是 sense 的“逆运算”，也是滤波器的核心。它回答的问题是：

“假设我的真实位置是 (self.x, self.y)，那么我观测到一个读数 measurement 的概率是多少？”

这个概率是通过一个二维高斯分布函数来计算的。测量值离真实位置越近，概率就越高。其数学形式为：
$P(\text{measurement} | \text{true_pos}) = \frac{1}{\sqrt{2\pi\sigma^2}} \exp\left(-\frac{(\text{measurement}_x - \text{true_pos}_x)^2}{2\sigma^2}\right) \times \frac{1}{\sqrt{2\pi\sigma^2}} \exp\left(-\frac{(\text{measurement}_y - \text{true_pos}_y)^2}{2\sigma^2}\right)$
其中 $\sigma$ 就是 self.measurement_noise。在粒子滤波器中，这个函数被用来计算每个粒子的“权重”。

第三章：核心挑战：横向跟踪误差 (Crosstrack Error, CTE)

在上一章，我们解剖了一个虽然功能完备但充满不确定性的机器人。现在，想象我们给这个机器人下达了一个任务：从 A 点沿着一条直线走到 B 点。由于存在各种噪声（steering_noise, distance_noise），机器人几乎不可能完美地走出一条直线。它会不断地偏离我们为它设定的理想路径。

为了能将它“拉”回正轨，我们首先需要一个量化的指标来描述它到底“偏了多少”、“偏向了哪边”。这个指标，就是横向跟踪误差 (Crosstrack Error, CTE)。

3.1 💡 什么是 CTE？

简单来说，CTE 就是机器人当前位置到预定路径的最短垂直距离。

  • 如果 CTE 是 0，意味着机器人正好在路径上。
  • 如果 CTE 是一个正数，可能意味着它在路径的右侧。
  • 如果 CTE 是一个负数，可能意味着它在路径的左侧。

这个带有正负号的误差值，对于控制器来说是至关重要的信息，因为它直接告诉控制器应该向哪个方向转向来修正错误。

3.2 📐 CTE 的数学推导：从几何到向量

这是本课程的一个核心数学知识点，也是考试中极有可能出现的计算题。让我们一步步拆解它。

假设我们的预定路径是一条由点 $P_1 = (x_1, y_1)$ 指向点 $P_2 = (x_2, y_2)$ 的线段。而我们的机器人通过粒子滤波器等方式，估计自己当前的位置在 $P = (x, y)$。

我们的目标是计算出图中红线代表的 CTE 值，以及一个辅助值 u，它代表了机器人在路径上的前进进度。

第一步：定义向量

我们将这个问题向量化，这样可以利用向量工具来简化计算。

  • 路径向量 (Path Vector) $\vec{\Delta}$：从路径起点 $P_1$ 指向终点 $P_2$。
    $\vec{\Delta} = P_2 - P_1 = (\Delta_x, \Delta_y) = (x_2 - x_1, y_2 - y_1)$
  • 机器人相对向量 (Robot Vector) $\vec{R}$：从路径起点 $P_1$ 指向机器人当前位置 $P$。
    $\vec{R} = P - P_1 = (R_x, R_y) = (x - x_1, y - y_1)$

第二步：计算前进进度 u

在计算 CTE 之前，我们先计算机器人沿着路径方向“前进”了多远。这个进度 u 是通过将机器人向量 $\vec{R}$ 投影 (Project) 到路径向量 $\vec{\Delta}$ 上得到的。

在向量数学中，一个向量 $\vec{R}$ 在另一个向量 $\vec{\Delta}$ 上的投影长度与 $\vec{\Delta}$ 长度的比值，可以用点积 (Dot Product) 来高效计算：

$u = \frac{\vec{R} \cdot \vec{\Delta}}{\vec{\Delta} \cdot \vec{\Delta}} = \frac{R_x \Delta_x + R_y \Delta_y}{\Delta_x^2 + \Delta_y^2}$

  • u 的含义:
    • 0 ≤ u ≤ 1: 机器人的投影点在线段 $P_1P_2$ 之间，这是正常情况。
    • u > 1: 机器人的投影点已经超出了终点 $P_2$。⚠️ 这是一个重要的信号！它告诉我们的程序，机器人已经完成了当前线段的跟踪，应该切换到路径的下一段了。
    • u < 0: 机器人的投影点还在起点 $P_1$ 之后。

第三步：计算横向跟踪误差 CTE

CTE 是 $\vec{R}$ 在垂直于 $\vec{\Delta}$ 方向上的分量。我们可以利用二维向量叉积 (Cross Product) 的几何意义来计算。两个向量 $\vec{A}=(a_x, a_y)$ 和 $\vec{B}=(b_x, b_y)$ 的“二维叉积”可以定义为 $a_x b_y - a_y b_x$，其绝对值等于这两个向量构成的平行四边形的面积。

因此，CTE（即 $\vec{R}$ 相对 $\vec{\Delta}$ 的垂直高度）可以表达为：

$\text{CTE} = \frac{\text{Area of Parallelogram}}{||\text{Base Vector}||} = \frac{|R_x \Delta_y - R_y \Delta_x|}{||\vec{\Delta}||}$

为了得到方向（即判断在左侧还是右侧），我们去掉绝对值。课程中给出的公式，为了计算方便，使用了与 u 相同的分母（即路径长度的平方），这在作为 PD 控制器的输入时是可行的，因为它保留了最重要的符号和相对大小。

$\text{CTE}_{\text{lecture}} = \frac{R_y \Delta_x - R_x \Delta_y}{\Delta_x^2 + \Delta_y^2}$

⚠️ 教师注: 严格来说，CTE 的物理单位应该是米，所以分母应该是路径的长度 $\sqrt{\Delta_x^2 + \Delta_y^2}$。但在课程的编程实践中，使用长度的平方作为分母是可以通过测试的，因为它能正确地驱动控制器。关键在于理解其数学本质。

2.3 考点聚焦：公式应用

模拟考题 📝

问题: 假设一个机器人正在跟踪一条从 $P_1 = (2, 2)$ 到 $P_2 = (10, 8)$ 的路径。它的粒子滤波器估计其当前位置为 $P = (5, 7)$。请计算：

  1. 机器人在该路径上的前进进度 u。
  2. 根据课程讲义中的公式计算横向跟踪误差 CTE。
  3. CTE 的计算结果是正还是负？这通常意味着机器人在路径的哪一侧？

参考答案:

  1. 计算向量:
  • $\Delta_x = 10 - 2 = 8$
  • $\Delta_y = 8 - 2 = 6$
  • $R_x = 5 - 2 = 3$
  • $R_y = 7 - 2 = 5$
  1. 计算 u:
    $u = \frac{(3)(8) + (5)(6)}{8^2 + 6^2} = \frac{24 + 30}{64 + 36} = \frac{54}{100} = 0.54$
    因为 0 < 0.54 < 1，机器人正在正常跟踪此路径段。
  2. 计算 CTE:
    $\text{CTE}_{\text{lecture}} = \frac{(5)(8) - (3)(6)}{8^2 + 6^2} = \frac{40 - 18}{100} = \frac{22}{100} = 0.22$
  3. 分析:
    CTE 结果为 +0.22，是一个正数。通常，这表示机器人偏离在路径前进方向的“左侧”（这取决于坐标系和叉积的定义，但关键是控制器能一致地理解符号，例如，正号代表需要向右打方向盘）。

本章我们攻克了整个控制与导航任务的数学核心：横向跟踪误差 (CTE)。我们不仅理解了它的物理意义，还掌握了如何通过向量运算精确地计算出 CTE 和前进进度 u。

有了这个强大的数学工具，我们就从“无法衡量”进入了“可以量化”的阶段。我们现在可以精确地告诉机器人：“你偏离了路径 0.22 个单位，并且已经走完了这段路的 54%”。

🤔 思考与探索 (Follow-up Questions)

  1. 问题: 在我们的 CTE 计算中，我们使用的是机器人估计的位置 (x, y)，而不是它真实的物理位置。为什么要这样做？这对于整个系统有什么影响？

    参考答案: 因为在现实世界中，机器人永远无法知道自己绝对真实的位置。它所能依赖的只有通过传感器和滤波器得出的最优估计。因此，所有的控制决策都必须基于这个“信念”(Belief) 而非“真理”(Ground Truth)。这使得整个系统的表现依赖于滤波器的精度：一个准确的定位估计会带来精确的控制；反之，一个糟糕的定位估计则可能导致错误的控制决策，使机器人进一步偏离路径。

  2. 问题: 如果路径是一条垂直线（即 $x_1 = x_2$），我们的 CTE 公式还能正常工作吗？

    参考答案: 可以。如果 $x_1 = x_2$，那么 $\Delta_x = 0$。此时 CTE 公式变为 $\frac{R_y \cdot 0 - R_x \cdot \Delta_y}{0^2 + \Delta_y^2} = \frac{-R_x \Delta_y}{\Delta_y^2} = \frac{-R_x}{\Delta_y}$。这与机器人和路径之间的水平距离成正比，方向由 $R_x$ 和 $\Delta_y$ 的符号决定，所以公式依然有效。

4.3 考点聚焦：代码逻辑与边界情况

模拟考题 📝

问题: 在实现 CTE 的计算和路径切换逻辑时，一个常见的错误是在 index 增加后忘记了处理一种边界情况，这可能导致程序崩溃。请问这个边界情况是什么？并描述至少一种处理该情况的策略。

参考答案:

边界情况: 当机器人跟踪的是路径的最后一段线段时（即 index 等于 len(spath) - 2），如果 u > 1，程序会执行 index += 1。此时 index 变为 len(spath) - 1。在下一次循环中，代码试图访问 spath[index + 1]，即 spath[len(spath)]，这将导致 “index out of bounds”（索引越界）错误，从而使程序崩溃。

处理策略:

  1. 策略一 (检查索引): 在循环的开始或在访问 spath[index + 1] 之前，添加一个检查。如果 index >= len(spath) - 1，说明已经到达或超过了路径的最后一个点，此时应该跳出循环，或者将 CTE 设为 0，不再进行计算。
