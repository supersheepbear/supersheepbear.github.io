TCP拥塞控制原理总结

🧑‍💻 User

Close

We begin with a general discussion about how TCP controls congestion. It decreases the window when the level of congestion goes up, and it increases the window when the level of congestion goes down. We refer to this combined mechanism as additive increase/multiplicative decrease (AIMD).

Additive Increase

The connection starts with a constant initial window, typically 2, and increases it additively. The idea behind additive increase is to increase the window by one packet every RTT (Round Trip Time). So, in the additive increase part of the AIMD, every time the sending host successfully sends a CongestionWindow (cwnd) number of packets it adds 1 to cwnd.

Also, in practice, this increase in AIMD happens incrementally. TCP does not wait for ACKs of all the packets from the previous RTT. Instead, it increases the congestion window size as soon as each ACK arrives. In bytes, this increment is a portion of the MSS (Maximum Segment Size).

Increment = MSS × (MSS / CongestionWindow)

CongestionWindow += Increment

Congestion control at TCP - AIMD-1

Multiplicative Decrease

Once TCP detects congestion, it reduces the rate at which the sender transmits. So, when the TCP sender detects that a loss event has occurred, then it sets cwnd to half of its previous value. This decrease of the cwnd for each timeout corresponds to the “multiplicative decrease” part of AIMD. For example, suppose the cwnd is currently set to 16 packets. If a loss is detected, then cwnd is set to 8. Further losses would result in the cwnd to be reduced to 4, and then to 2, and then to 1. The value of cwnd cannot be reduced further than a value of 1 packet.

TCP continually increases and decreases the congestion window throughout the lifetime of the connection. If we plot cwnd with respect to time, we observe that it follows a sawtooth pattern as shown in the figure:

Congestion control at TCP - AIMD-3

TCP Reno

Different implementations of TCP use variations to control congestion and maximize bandwidth usage. For example, TCP Reno uses two types of loss events as a signal of congestion. The first is the triple duplicate ACKs, which is considered mild congestion. In this case, the congestion window is reduced to half the original.

The second kind of congestion detection is timeout, i.e., when no ACK is received within a specified amount of time. It is considered a more severe form of congestion, and the congestion window is reset to the initial window size.

✅ 参考答案

问题 1：我能用一句话解释什么是 AIMD 吗？

答案：AIMD 是 TCP 的拥塞控制机制——当网络通畅时缓慢增加发送速率（每 RTT 加 1），当检测到拥塞时快速减半发送速率。

问题 2：为什么 TCP 要同时使用”加性增加”和”乘性减少”？

答案：

  • 加性增加：谨慎地探测网络容量，避免突然增加太多导致拥塞
  • 乘性减少：快速响应拥塞，迅速降低负载，防止网络崩溃
  • 组合效果：在效率和稳定性之间取得平衡

问题 3：cwnd (Congestion Window) 是什么？

答案：cwnd 是发送方维护的一个变量，表示在收到 ACK 之前可以发送的最大数据量（以 packets 或 bytes 计）。它控制着发送速率。

问题 4：加性增加的核心规则是什么？

答案：每经过一个 RTT (Round Trip Time)，cwnd 增加 1 个 packet。

问题 6：为什么 TCP 每收到一个 ACK 就增加窗口？

答案：这是增量式实现 (incremental implementation)。TCP 不等待一个 RTT 内所有 ACK 到达，而是每收到一个 ACK 就增加一小部分，这样响应更及时、更平滑。

问题 7：检测到拥塞时，cwnd 如何变化？

答案：cwnd 被设置为当前值的一半 (half)。

问题 8：cwnd = 16，连续 3 次丢包后变成多少？

答案：

  • 第 1 次丢包：16 → 8
  • 第 2 次丢包：8 → 4
  • 第 3 次丢包：4 → 2

最终 cwnd = 2

问题 9：cwnd 的最小值是多少？

答案：1 packet，不能再低了。

问题 10：TCP Reno 中两种拥塞信号是什么？

答案：
| 信号类型 | 严重程度 | 响应方式 |
|————-|————-|————-|
| Triple Duplicate ACKs (三次重复ACK) | 轻度拥塞 (mild) | cwnd 减半 |
| Timeout (超时) | 严重拥塞 (severe) | cwnd 重置为初始值 |

问题 11：Triple Duplicate ACKs 触发什么响应？

答案：cwnd 减半（乘以 0.5）。

问题 12：Timeout 触发什么响应？

答案：cwnd 重置为初始窗口大小 (initial window size)，通常是 2。

问题 13：为什么两种情况处理方式不同？

答案：

  • Triple Duplicate ACKs：说明网络还在传输数据（能收到重复 ACK），只是部分丢包，拥塞较轻
  • Timeout：说明完全收不到任何响应，网络可能严重拥塞，需要更激进地降速

问题 14：锯齿图 (sawtooth pattern) 是什么样的？

答案：

Code

  • 斜向上：加性增加阶段
  • 垂直下降：检测到拥塞，乘性减少

问题 15：”Probing” 是什么意思？

答案：TCP 发送方不断试探网络容量——逐渐增加发送速率直到发生拥塞，然后退回，再继续试探。这是一个持续的”探测-退回-再探测”循环。

问题 16：生活比喻解释 AIMD

答案：想象你在高速公路上开车：

  • 加性增加：路况好时，你每分钟加速 5 km/h，小心翼翼地提速
  • 乘性减少：一旦看到前方堵车（拥塞），你立刻把速度减半
  • 锯齿模式：你不断加速→遇堵→减速→再加速，速度曲线像锯齿
  • Probing：你在试探”这条路最快能开多快而不堵”
