进程与进程管理 (Processes and Process Management)

第一部分：进程基础概念

1.1 课程预览 (Lesson Preview)

欢迎来到进程与进程管理的课程。进程(Process)是操作系统支持的最关键的抽象之一，理解进程对于深入学习操作系统至关重要。

在本课程中，我们将系统地探讨以下核心问题：

首先，我们将解释什么是进程(What is a Process)，建立对进程概念的基本认识。

其次，我们将深入了解操作系统如何表示一个进程(How an Operating System Represents a Process)，包括进程在内存中的布局以及操作系统用于管理进程的数据结构。

第三，我们将探讨操作系统必须执行哪些操作来管理一个或多个进程(What an Operating System Must Do to Manage Processes)，特别是当多个进程共享同一个物理平台时，操作系统如何协调它们。

在正式开始之前，让我们先给出进程的基本定义：

用最简单的话来说，进程是一个正在执行的程序的实例(An Instance of an Executing Program)。

有时候，我们也会使用任务(Task)或作业(Job)这两个术语来与进程互换使用，它们在很多语境下表达的是相同的概念。

1.2 视觉隐喻：玩具订单 (Visual Metaphor: Toy Order)

为了帮助你更直观地理解进程的本质，我们继续使用玩具店的比喻。在这个比喻中，你可以把进程想象成一份玩具订单(An Order of Toys)。

1.2.1 玩具订单的特征

一份玩具订单具有以下特征：

执行状态 (State of Execution)

  • 订单有其执行状态，例如：已完成的玩具、等待制作的玩具，以及其他相关信息
  • 这些状态信息描述了订单当前处于什么阶段

所需零件 (Required Parts)

  • 制作玩具需要各种零件，比如塑料件、木制件等
  • 这些零件装在不同的容器中

临时存放区域 (Temporary Holding Area)

  • 制作过程中可能需要一些临时存放零件的区域

特殊硬件 (Special Hardware)

  • 实际制作玩具可能需要一些特殊的硬件设备
  • 例如：缝纫机(Sewing Machines)、热熔胶枪(Glue Guns)或其他类型的工具

1.2.2 进程与玩具订单的对应关系

那么，这一切如何与操作系统中的进程相对应呢？

玩具订单 进程
执行状态（已完成/待制作的玩具） 执行状态，由程序计数器(Program Counter)和栈指针(Stack Pointer)描述
所需零件（塑料件、木制件） 执行所需的数据(Data)，存储在寄存器(Registers)中的状态
临时存放区域 内存(Memory)中占用的状态
特殊硬件（缝纫机、胶枪） I/O设备(I/O Devices)，如磁盘、网络设备

关于执行状态：操作系统使用程序计数器、栈指针等信息来决定如何调度进程(Schedule the Process)、如何在多个进程之间切换(Swap Between Multiple Processes)，以及执行其他管理任务。

关于数据和内存：为了执行，进程需要一些数据。有些状态存储在寄存器中，进程还会在内存中占用一些临时存放区域。

关于特殊硬件：执行一个进程可能需要一些特殊的硬件，比如I/O设备（磁盘或网络设备）。操作系统必须管理这些设备，并控制哪些可能同时执行的进程可以访问哪些硬件组件。

这就像玩具店经理必须控制特殊硬件（如缝纫机或热熔胶枪）的使用方式一样——决定哪个特定的玩具订单将被分配使用这些指定的硬件组件。

1.3 什么是进程 (What is a Process)

现在让我们更具体地讨论进程。首先，我们需要理解什么是进程。

1.3.1 回顾操作系统的角色

回想一下，操作系统的角色之一是代表应用程序管理硬件(Manage the Hardware on Behalf of Applications)。

1.3.2 应用程序与进程的区别

这里有一个非常重要的区分：

应用程序 (Application)：

  • 是一个存储在磁盘(Disk)、闪存(Flash Memory)甚至云端(Cloud)的程序
  • 它没有在执行
  • 它是一个静态实体(Static Entity)

例如，我们有一个应用程序存储在磁盘上。

进程 (Process)：

  • 一旦应用程序被启动(Launched)，它就被加载到内存(Memory)中
  • 然后它开始执行(Executing)
  • 此时它就变成了一个进程
  • 所以进程是一个活动实体(Active Entity)

1.3.3 同一程序的多个进程

如果同一个程序被启动多次，将会创建多个进程。这些进程执行的是相同的程序，但它们可能具有非常不同的状态——事实上，它们很可能具有非常不同的状态。

示例：文字编辑器

假设你使用同一个文字编辑器程序：

进程1：

  • 是文字编辑器程序的一个实例
  • 正在显示上一节课的笔记
  • 你只是在复习它，并没有真正修改它

进程2：

  • 是完全相同的文字编辑器程序的另一个实例
  • 用于记录本节课的笔记
  • 鉴于课程刚刚开始，这个进程可能没有太多笔记
  • 所以它的状态相对较小
  • 它可能有一些未保存的编辑

1.3.4 进程的本质

因此，进程代表了一个活动应用程序的执行状态(Execution State of an Active Application)。

需要特别注意的是：进程处于活动状态并不一定意味着它正在运行(Running)。

进程可能处于以下状态：

  • 等待输入：例如等待用户输入来键入某些笔记
  • 等待CPU：可能正在等待另一个当前在CPU上运行的进程（如果系统中只有一个CPU的话）

这个区分非常重要：进程是活动的，但它不一定在任何给定时刻都在CPU上执行。

本部分小结

在第一部分中，我们学习了：

  1. 进程的定义：进程是正在执行的程序的实例，是一个活动实体
  2. 应用程序与进程的区别：应用程序是静态的（存储在磁盘上），进程是动态的（加载到内存中执行）
  3. 进程的特征：通过玩具订单的比喻，我们理解了进程具有执行状态、所需数据、内存空间和硬件需求
  4. 多进程概念：同一程序可以创建多个进程，每个进程有独立的状态

进程与进程管理 (Processes and Process Management)

第二部分：进程的内存表示

2.1 进程的结构 (What Does a Process Look Like)

现在让我们来看看进程在内存中是什么样子的。

2.1.1 进程封装的数据

一个进程封装了运行应用程序所需的所有数据，包括：

  • 代码(Code)：程序的指令
  • 数据(Data)：程序使用的数据
  • 变量(Variables)：应用程序需要分配的所有变量

2.1.2 地址空间的概念

进程状态的每一个元素都必须通过其地址(Address)来唯一标识。因此，操作系统使用一个抽象来封装所有的进程状态，这个抽象叫做地址空间(Address Space)。

地址空间由一个地址范围定义，从V0到某个Vmax。不同类型的进程状态将出现在这个地址空间的不同区域中。

2.1.3 进程状态的不同类型

进程中有哪些不同类型的状态呢？让我们从下到上来看：

代码和数据段 (Code/Text and Data)

首先，我们有代码（也称为文本段/Text）和数据，这些在进程首次初始化时就已经可用。这些都是静态状态(Static State)，在进程首次加载时就存在。

堆 (Heap)

在执行过程中，进程会动态地创建一些状态：

  • 分配内存
  • 存储临时结果
  • 从文件读取数据

这部分地址空间我们称之为堆(Heap)。

需要注意的是，虽然在概念图中堆通常被显示为紧接在数据段之后的连续部分，但实际上堆可能存在空洞(Holes)：

  • 它可能不是连续的
  • 可能有些部分对该特定进程没有任何意义
  • 事实上，进程甚至不被允许访问这些部分

栈 (Stack)

地址空间的另一个非常重要的部分是栈(Stack)。

栈的特点：

  • 它是地址空间状态的动态部分(Dynamic Part)
  • 在执行过程中会增长和收缩
  • 但它以后进先出(Last-In, First-Out, LIFO)的顺序进行操作
  • 无论你放在栈上的是什么，当你尝试从栈中读取时，它将是第一个被返回的项目

2.1.4 栈的工作原理示例

让我们通过一个例子来理解栈的工作方式：

场景：假设我们正在执行进程的某个特定部分，现在需要调用某个过程(Procedure)，跳转到地址空间的另一个部分。

步骤1：保存状态

  • 我们希望确保在调用这个其他过程之前，当前执行点的状态被保存
  • 这样当我们从执行返回时，状态可以被恢复

步骤2：压栈

  • 我们可以将状态X放在栈上
  • 然后跳转去执行代码的另一部分（过程Y）

步骤3：出栈恢复

  • 当我们完成Y的执行后
  • 状态X将从栈中弹出(Pop)
  • 我们可以在调用Y之前的相同状态下继续执行

在进程执行过程中，有很多地方这种后进先出的行为非常有用，所以栈是一个非常有用的数据结构。

2.2 进程地址空间 (Process Address Space)

作为一个整体，我们将这种进程表示称为地址空间(Address Space)。

2.2.1 虚拟地址的概念

我们之前说过，从V0到Vmax的潜在地址范围代表了进程地址空间的最大大小。我们称这些地址为虚拟地址(Virtual Addresses)。

V0到Vmax之间的地址是进程用来引用其某些状态的地址。

为什么称为”虚拟”？

我们称这些地址为虚拟的，是因为它们不必对应于物理内存中的实际位置。

2.2.2 地址映射机制

相反，内存管理硬件(Memory Management Hardware)和负责内存管理的操作系统组件（如页表/Page Tables）维护着虚拟地址和物理地址之间的映射。

通过使用这种类型的映射，我们将以下两者解耦：

  • 虚拟地址空间中的数据布局：这可能很复杂，可能取决于应用程序的具体情况或我们使用的工具（比如编译器如何选择布局数据）
  • 物理内存中的数据布局：这与虚拟布局完全分离

这种解耦允许我们保持物理内存管理的简单性，而不受正在执行的进程的数据布局的任何影响。

2.2.3 地址映射示例

让我们看一个具体的例子：

假设变量X在虚拟地址空间中的位置是03c5，这可能对应于物理内存中完全不同的地址0f0f。

映射过程：

  1. 当进程请求在特定虚拟地址分配一些内存时
  2. 操作系统实际分配的物理内存地址可能完全不同
  3. 操作系统不会通知进程关于变量实际在内存中的确切位置的细节
  4. 相反，操作系统会创建一个从虚拟地址(03c5)到物理地址(0f0f)的映射，这就是X实际所在的位置

访问过程：

  1. 每当进程尝试访问X时，这个映射就会被引用
  2. 实际上，X所在的确切物理位置将被访问
  3. 只要03c5和0f0f之间的映射存在于映射表中（这是一个页表/Page Table，映射条目称为页表项/Page Table Entry）
  4. 进程对X的任何访问实际上都会访问X存储的正确物理位置

2.3 地址空间与内存管理 (Address Space and Memory Management)

2.3.1 地址空间的实际使用

我们已经说过，并非所有进程都需要从V0到Vmax的整个地址空间。地址空间中可能有些部分是未分配的。

此外，即使我们确实需要所有这些状态，我们也可能根本没有足够的物理内存来存储它。

示例：

  • 如果我们有32位长的虚拟地址，这个地址空间可以达到4GB
  • 如果我们有多个这样的进程同时运行
  • 即使在相当昂贵的机器上，我们也会很快耗尽物理内存

2.3.2 操作系统的动态内存管理

为了处理这个问题，操作系统动态地决定哪个地址空间的哪个部分将出现在物理内存的哪个位置。

示例场景：

假设系统中有进程P1和P2，它们可能以这种方式共享物理内存：

  • 标记为黄色的区域属于P1
  • 标记为粉色的区域属于P2

P1和P2都可能有其地址空间的某些部分不在内存中，而是临时交换到磁盘(Swapped to Disk)上。

当需要时，地址空间的这部分将被带入内存。这可能会导致P1或P2地址空间的其他部分被交换到磁盘上以腾出空间。

2.3.3 操作系统维护的信息

因此，操作系统必须维护关于这些虚拟地址实际在哪里（在内存中还是在磁盘上）的信息。

操作系统维护着虚拟地址和进程地址空间每个部分的物理位置之间的映射。我们提到了页表就是用于此目的的。

操作系统使用这些信息来：

  1. 维护虚拟地址和状态实际存储的物理位置之间的映射
  2. 检查内存访问的有效性，确保进程实际上被允许执行某个内存访问

虽然内存管理的详细内容将在后续课程中讨论，但至少你必须理解：对于每个进程，操作系统必须维护一些关于进程地址空间的信息。

2.4 虚拟地址测验 (Virtual Addresses Quiz)

2.4.1 测验问题

为了复习这些内容，让我们做一个测验。

问题：如果两个进程P1和P2同时运行，它们的虚拟地址空间范围是什么？

选项：

选项 P1的地址范围 P2的地址范围
A 0 到 32,000 32,001 到 64,000
B 0 到 64,000 0 到 64,000
C 32,001 到 64,000 0 到 32,000

请标记所有你认为正确的答案。

2.4.2 测验答案

正确答案是B。

P1和P2都可以拥有完全相同的虚拟地址空间范围，在这个例子中是从0到64,000。

解释：

操作系统在底层会将P1的虚拟地址映射到某些物理位置，将P2的虚拟地址映射到其他物理位置。

我们将进程使用的虚拟地址与数据实际所在的物理地址解耦这一事实，使得不同的进程可以拥有完全相同的地址空间范围并使用完全相同的地址成为可能。

如果需要的话，操作系统会确保它们指向不同的物理内存位置。

关键理解：

  • 虚拟地址是进程看到的地址
  • 物理地址是数据实际存储的位置
  • 操作系统负责维护两者之间的映射
  • 这种设计允许多个进程使用相同的虚拟地址范围而不会冲突

本部分小结

在第二部分中，我们学习了：

  1. 进程的内存结构：

    • 代码/文本段(Code/Text)：程序指令
    • 数据段(Data)：静态数据
    • 堆(Heap)：动态分配的内存，可能不连续
    • 栈(Stack)：后进先出的动态数据结构

  2. 虚拟地址空间：

    • 进程使用虚拟地址引用其状态
    • 虚拟地址不必对应物理内存的实际位置
    • 页表维护虚拟地址到物理地址的映射

  3. 内存管理：

    • 操作系统动态决定哪些数据在物理内存中
    • 部分数据可能被交换到磁盘
    • 多个进程可以共享物理内存
    • 不同进程可以有相同的虚拟地址范围
