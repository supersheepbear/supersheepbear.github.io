实测多款大模型（LLM）用同一提示词开发B站首页：谁才是真正的 Coding 之神？

一、这期视频在干什么？

作者团队做了一件事：用同一套提示词（prompt），让十几款主流大模型（Large Language Model）同时去完成同一个开发任务，然后对比它们的实际表现。

为什么要这么做？因为各家模型厂商都喜欢晒跑分（benchmark），说自己多强多强。但跑分高 ≠ 实际开发能力强。作者想用一个真实的、有一定复杂度的项目，来”验货”。

二、开发任务是什么？

任务：做一个仿哔哩哔哩（Bilibili）的视频平台网站。

听起来很难，但作者做了一个简化：GitHub 上有一个开源的第三方库（third-party library）叫 bilibili-API，它把 B 站对外公开的各种接口（API）封装成了 Python 可以直接调用的函数。所以模型不需要自己去爬数据，只需要调用这个库就行。

这个设计很巧妙，因为它可以同时考察模型的多个能力：

  • 指令遵循度（instruction following）：模型是乖乖用这个第三方库，还是自己去写 HTTP 请求？
  • 架构设计能力（architecture design）：模型会选什么技术栈？用静态 HTML 三件套，还是用 React 这种框架？后端用什么？
  • 理解能力：模型能不能理解这是一个 Web 应用，而不是桌面应用？

具体功能要求

作者给了三个层级的功能需求：

  1. 基础功能：能播放 B 站视频、点击可跳转官网、展示点赞/投币/收藏/播放量等信息
  2. 中级功能：能查看评论和弹幕（通过调用 API）、能扫码登录 B 站并在本地保存登录状态（session）
  3. 高级功能：登录后能发评论、发弹幕、查看自己的收藏视频等

前端要求

  • 必须采用 B 站的 UI 风格（粉色主题色、网格布局等）
  • 界面必须是中文
  • UI 布局要合理

这考验模型的设计能力和训练数据质量——模型在训练时有没有”见过”B 站长什么样。

提示词风格

作者故意写得比较口语化、不那么文档化，因为这更贴近真实开发场景——大多数时候开发者不会写非常详尽的需求文档。

三、测了哪些模型？用什么工具？

一共约 15 个模型，涵盖海外和国内主流厂商：

海外三巨头：

  • ChatGPT 5.4、ChatGPT 5.3（OpenAI）
  • Claude 4.6 Opus（Anthropic）
  • Gemini 3.0 Pro、Gemini 3.0 Flash、Gemini 3.1 Pro（Google）

国内模型：

  • GLM 5、GLM 4.6（智谱）
  • Kimi K2.5（月之暗面，分官网 API 版和第三方优云智算版）
  • DeepSeek V3.2
  • 豆包 Seed 2.0 Pro（字节跳动）
  • 千问 3.5 Plus（阿里）
  • MiniMax M2.5
  • Step 3.5 Flash（阶跃星辰）
  • MiMo VR Flash（小米）

其他：

  • Grok 4.1 Thinking Fast（xAI）

开发工具选择原则

  • 如果厂商有自己的 CLI 开发工具（如 OpenAI 的 Codex、Anthropic 的 GitHub Copilot），就用自家的
  • 如果没有，统一用开源的 OpenCode（而不是 Claude Code），因为 Claude Code 内部会用一个辅助小模型，可能影响测试公平性
  • OpenCode 只用一个模型完成全程请求，更能代表主干模型本身的能力

四、测评结果：核心发现

声明：每个模型只测了一轮，可能存在”抽卡”运气成分，但作者认为任务复杂度足够高，结果仍有参考价值。

总榜排名（从高到低）

排名 模型 总分 核心特点
1 ChatGPT 5.4 82 后端最强、架构最佳、指令遵循最好，前端稍弱
2 ChatGPT 5.3 Codex 紧随其后 和 5.4 类似，前端弱但后端强
3 Claude 4.6 Opus 接近 5.3 综合最均衡，前端极强，但后端有幻觉（hallucination）问题
4 GLM 5 中上 国产版”迷你 Claude”，各方面不错但都弱一档
5 Gemini 3.0 Pro 中上 前端全场第一，但后端错误率高
6 Kimi K2.5（官网API） 中等 国产前端最好，但存在 mock 数据和 bug
7 MiMo VR Flash 中等偏下 小米模型，表现一般
8 Step 3.5 Flash 较低 搭了框架但内容没实现
9 千问 3.5 Plus 较低 同上，搭了框但内容空
10 MiniMax M2.5 较低 页面框架有，内部实现不完整
11 Gemini 3.1 Pro 较低 相比 3.0 Pro 反而退步了（”倒吸牙膏”）
12 DeepSeek V3.2 很低 连页面都搭不出来，直接返回 JSON
13 Gemini 3.0 Flash 很低 模型体量不够，无法完成任务
14 Kimi K2.5（第三方API） 很低 疑似量化版本，质量暴跌约 30%
15 豆包 Seed 2.0 Pro 很低 全是假数据（mock data），”造假”严重
16 Grok 4.1 极低 把任务理解成桌面应用，方向完全错
17 GLM 4.6（对照组） 最低（1分） 2025年10月的老模型，已无法完成此任务

五、海外三巨头的特点对比

这是本视频最核心的结论，可以用一句话概括每家的”性格”：

ChatGPT 系列（OpenAI）：后端之王，前端审美差

  • 逻辑能力极强，所有功能都能实现，登录、评论、弹幕全部搞定
  • 但页面交互设计很奇怪，布局不合理，看着不舒服
  • 作者推测：训练数据中后端/逻辑类数据占比更高，前端设计类数据不足
  • 5.4 比 5.3 在 UI 上有改善，但仍不如 Claude
  • 适合场景：后端开发、重构、逻辑密集型任务

Claude 系列（Anthropic）：综合最均衡，适合做产品

  • 做出来的界面和 B 站官方非常接近，粉色主题、网格布局都对
  • 但后端存在幻觉（hallucination）问题——明明查到了正确的 API，后面却调错了接口
  • 比如登录功能就因为调错 API 而失败
  • 前后端数据质量比例更均衡
  • 适合场景：快速原型开发（rapid prototyping）、产品设计、架构规划

Gemini 系列（Google）：前端之神，后端拉胯

  • Gemini 3.0 Pro 的前端是全场第一，布局、数据展示几乎和 B 站官网一模一样
  • 但后端错误率比 GLM 还高
  • 3.0 Flash 由于模型体量小，智力不够，基本做不了这个任务
  • 3.1 Pro 反而比 3.0 Pro 退步了，指令遵循和前端理解都变差
  • 适合场景：前端开发、UI 优化、SVG 图标生成

类比理解：把这三家想象成三个程序员——ChatGPT 是后端大佬，代码逻辑无敌但审美为零；Claude 是全栈工程师，前后端都行但偶尔粗心；Gemini 是前端设计师，页面做得漂亮但后端一塌糊涂。

六、国内模型的共同问题

作者总结了一个很形象的说法：“有框没内容”。

国内模型普遍能把页面的大框架搭出来（顶部栏、侧边栏），但中间的实际内容（视频列表、真实数据）做不出来。登录功能几乎全军覆没。

几个值得注意的点

  • Kimi K2.5（官网版）是国产中最好的，前端甚至能和 Claude 比肩
  • 豆包 Seed 2.0 Pro 有严重的”造假”倾向——用 mock 数据（模拟假数据）糊弄，表面看着不错，实际全是假的
  • GLM 5 是国产中综合最均衡的，像一个”迷你版 Claude”
  • 千问 3.5 Plus 虽然最近很火，但实测只搭了个框，里面什么都没实现

七、第三方 API 部署的巨大风险

本次测试中一个重要发现：同一个模型，官网 API 和第三方 API 的表现可能天差地别。

Kimi K2.5 官网版排第 6，但通过优云智算部署的第三方版本几乎垫底。作者怀疑第三方可能部署了量化版本（quantized version），导致模型能力下降约 30%。

量化（quantization）简单理解：为了省成本，把模型的精度降低（比如从 16 位浮点数降到 8 位甚至 4 位），模型变小变快，但智力也会下降。

建议：尽量使用官方 API 或官方开发工具，不要为了省钱用第三方中转，否则可能浪费更多时间在调试上。

八、架构选择的差异

不同模型对同一任务选择了不同的技术架构（architecture），这本身就反映了模型的”思维深度”：

  • ChatGPT 5.4：选了 React（前端框架），考虑了可扩展性（scalability）
  • ChatGPT 5.3：选了静态前端三件套（HTML/CSS/JS），更简单直接
  • Claude 4.6 Opus：前后端都用单体架构（monolithic），追求快速实现
  • GLM 5：前后端都用了框架，表现不错
  • Gemini 3.0 Pro：虽然界面好看，但遗留了大量垃圾文件（历史版本未清理）

作者的结论：ChatGPT 5.4 在架构思考上最成熟，会优先考虑可维护性和可扩展性；Claude 更倾向于”先跑起来再说”。

九、实际开发建议

作者给出的最终建议：

  1. 主力开发用 ChatGPT 5.4——目前综合能力最强，尤其后端和架构
  2. 前端不满意就用 Gemini 3.0 Pro 优化——前端审美全场第一
  3. 资金充足可以用 Claude 4.6 Opus——综合均衡，适合快速出原型
  4. 国产首选 Kimi K2.5（官网版）写前端，后端用 GLM 5 多轮迭代
  5. 用豆包时要警惕 mock 数据——一定要在提示词中强制要求用真实数据，并仔细 code review
  6. 目前只有 ChatGPT 能做到自主 review 保证指令遵循，其他模型（包括 Claude）都需要人工仔细验证

费曼自检 Checklist

这次测评的开发任务是什么？为什么选这个任务？

answer 任务是用同一套提示词让多个大模型开发一个仿 B 站视频平台网站，使用 GitHub 上的 bilibili-API 第三方库获取数据。选这个任务是因为它能同时考察模型的指令遵循度、架构设计能力、前后端开发能力和对真实产品的理解能力，比单纯跑 benchmark 更能反映实际开发水平。

ChatGPT、Claude、Gemini 三家各自的核心优势和劣势是什么？

answer ChatGPT：后端逻辑极强，架构设计最好，指令遵循最佳，但前端交互设计和审美较差。Claude：综合最均衡，前端还原度高，适合做产品原型，但存在幻觉问题（会调错 API）。Gemini：前端全场第一，页面几乎和 B 站官网一样，但后端错误率高，整体可靠性不足。

为什么同一个模型（Kimi K2.5）在官网 API 和第三方 API 上表现差距这么大？

answer 第三方 API 服务商可能部署了量化版本（quantized version）的模型，降低了精度以节省成本，导致模型能力下降约 30%。表现为原本能正确对接的 API 对接不上，业务理解也出现问题。所以建议尽量使用官方 API。

国内模型的共同问题是什么？

answer "有框没内容"——能搭出页面的大框架（顶部栏、侧边栏），但中间的实际内容（真实视频数据、功能实现）做不出来。登录功能几乎全部失败。部分模型（如豆包）还有用 mock 假数据糊弄的倾向。

为什么测试工具选 OpenCode 而不是 Claude Code？

answer 因为 Claude Code 内部会使用一个辅助小模型，可能影响测试的公平性。而 OpenCode 只用一个模型完成全程请求，更能代表主干模型本身的真实能力。

作者给出的实际开发建议中，最核心的一条是什么？

answer 目前只有 ChatGPT 能做到自主 review 来保证指令遵循度，其他所有模型（包括 Claude 4.6 Opus）都无法保证完全执行需求，所以无论用哪个模型，都必须仔细进行人工 code review，验证需求是否被全部实现。
